Bloco 1

O que é o DuckDB

O problema com dados grandes no R

O R carrega todos os dados na memória antes de qualquer operação. Com dplyr, isso significa:

voos_grande |>
  group_by(origin) |>
  summarise(media = mean(arr_delay, na.rm = TRUE))

O R precisa:

  1. Carregar todas as 18 milhões de linhas na RAM
  2. Dividir em grupos
  3. Calcular a média de cada grupo
  4. Retornar o resultado
  • O dplyr é uma ferramenta construída para conveniência. Ao enfrentar datasets que crescem além de alguns gigabytes, ele revela sua principal limitação: é single-threaded e opera integralmente em memória.

O que é o DuckDB

  • DuckDB é um banco de dados analítico open-source, embutido, in-process, relacional e OLAP. Cada uma dessas palavras tem significado técnico preciso:

  • Open-source: lançado sob licença MIT. Código disponível, modificável e de uso livre.

  • Embutido: não existe como servidor separado. Roda dentro do processo do R, como uma biblioteca.

  • In-process: opera no mesmo espaço de memória do R. A comunicação é direta, sem serialização de rede.

  • OLAP: otimizado para consultas analíticas, agregações, filtros e joins sobre grandes volumes, não para transações individuais como inserções e atualizações.

DuckDB x SQLite

Ambos são bancos embutidos sem servidor. O propósito é oposto:

Característica SQLite DuckDB
Modelo OLTP OLAP
Otimizado para Muitas escritas individuais Leituras analíticas em massa
Armazenamento Orientado a linha Orientado a coluna
Paralelismo Single-thread Multi-thread nativo
Funções analíticas Básicas median(), quantile(), janelas
Leitura de Parquet Via extensão Nativa
Uso típico Apps, sistemas web Análise de dados, BI

DuckDB x dplyr:

con_bench <- dbConnect(duckdb())

bench::mark(
  dplyr = {
    nycflights13::flights |>
      filter(!is.na(arr_delay)) |>
      group_by(origin, carrier) |>
      summarise(
        n            = n(),
        atraso_medio = mean(arr_delay),
        .groups = "drop")
  },
  duckdb_parquet = {
    dbGetQuery(con_bench, "
      SELECT   origin, carrier,
               COUNT(*)         AS n,
               AVG(arr_delay)   AS atraso_medio
      FROM     'dados_duck/voos.parquet'
      WHERE    arr_delay IS NOT NULL
      GROUP BY origin, carrier")
  },
  iterations = 3,
  check = FALSE) |>
  select(expression, median, mem_alloc)

Output: dplyr x DuckDB

# expression       median    mem_alloc
# dplyr            142ms     52.4MB
# duckdb_parquet    38ms      2.1MB

O DuckDB leu o Parquet grande sem carregar tudo na RAM e completou a consulta em menos de 1/3 do tempo do dplyr sobre o mesmo dataset em memória.

Gerenciamento da conexão

# Sempre feche a conexão ao final do trabalho
dbDisconnect(con,      shutdown = TRUE)
dbDisconnect(con_file, shutdown = TRUE)

# Em funções, use on.exit() para garantir o fechamento
analisar_dados <- function(caminho) {
  con <- dbConnect(duckdb(), dbdir = caminho)
  on.exit(dbDisconnect(con, shutdown = TRUE), add = TRUE)

  dbGetQuery(con, "SELECT COUNT(*) FROM voos")
}

Important

Atenção: o DuckDB permite apenas uma conexão por arquivo ao mesmo tempo. Se você tentar abrir uma segunda conexão para o mesmo arquivo .duckdb, receberá um erro de bloqueio. Sempre feche a conexão antes de reconectar.

Funções de janela no DuckDB

Funções de janela calculam valores sobre um conjunto de linhas relacionadas à linha atual, sem colapsá-las em grupos. São fundamentais para rankings, médias móveis e comparações com o período anterior.

dbGetQuery(con, "
  SELECT   month,
           origin,
           ROUND(AVG(arr_delay), 2)    AS atraso_medio,
           ROUND(AVG(AVG(arr_delay)) OVER (
             PARTITION BY origin
             ORDER BY month
             ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
           ), 2)                       AS media_movel_3m
  FROM     flights
  WHERE    arr_delay IS NOT NULL
  GROUP BY month, origin
  ORDER BY origin, month") |>
  as_tibble()

Bloco 6

Integração com Arrow

Transferência zero-copy entre arrow e DuckDB

A integração zero-copy entre DuckDB e Apache Arrow permite análise rápida de datasets maiores que a memória disponível usando SQL ou APIs relacionais, sem serialização ou cópia de dados.

O que zero-copy significa tecnicamente:

Quando você chama to_duckdb() sobre um dataset arrow, o DuckDB recebe ponteiros para os buffers de memória do arrow, não cópias dos dados. Isso significa:

  • Nenhum dado é duplicado na memória
  • A operação é praticamente instantânea, independente do tamanho
  • Modificações no DuckDB não afetam o objeto arrow original

to_duckdb(): arrow para DuckDB

ds <- open_dataset("dados_duck/voos.parquet")

ds |>
  to_duckdb() |>
  filter(!is.na(arr_delay)) |>
  group_by(origin) |>
  summarise(
    n       = n(),
    media   = round(mean(arr_delay), 2),
    mediana = round(median(arr_delay), 2),
    q75     = round(quantile(arr_delay, 0.75), 2),
    .groups = "drop") |>
  collect()

to_arrow(): DuckDB de volta para arrow

# Iniciar no arrow, passar para DuckDB, voltar para arrow
# sem materializar na memória do R em nenhum passo intermediário
resultado_arrow <- open_dataset("dados_duck/voos.parquet") |>
  to_duckdb() |>
  filter(!is.na(arr_delay), month %in% c(6, 7, 8)) |>
  group_by(origin, month) |>
  summarise(
    atraso_medio   = mean(arr_delay),
    atraso_mediano = median(arr_delay),
    .groups = "drop") |>
  to_arrow()

Quando usar to_duckdb() no meio de um pipeline

Use to_duckdb() quando:

  • Precisar de median(), quantile() ou funções de janela em dados Parquet grandes
  • O pipeline arrow encontrar um erro de tradução SQL
  • Precisar de SQL complexo que o dbplyr não consegue gerar

Use to_arrow() para voltar quando:

  • O resultado precisa ser escrito como Parquet com write_dataset()
  • A próxima operação é melhor suportada pelo arrow do que pelo DuckDB
  • Você quer evitar collect() e manter os dados fora da RAM

duckplyr

O que é o duckplyr

  • duckplyr é um pacote que substitui o backend padrão do dplyr pelo motor de consultas do DuckDB, sem precisar de dbConnect(), tbl() ou collect() explícitos.

  • Com o dplyr convencional, você escreve R que vira C++.

  • Com o duckplyr, você escreve dplyr que vira SQL nativo do DuckDB.

  • A diferença em relação ao dbplyr com DuckDB:

  • dbplyr traduz dplyr para SQL genérico via DBI, depois o banco executa.

  • duckplyr traduz dplyr diretamente para o plano relacional interno do DuckDB, sem intermediários.

Extensões do DuckDB

O sistema de extensões do DuckDB

  • O DuckDB tem um sistema de extensões que adiciona funcionalidades sem precisar reinstalar o pacote. Extensões são instaladas uma vez e carregadas por sessão.
con <- dbConnect(duckdb())

# Instalar uma extensão (necessário apenas uma vez)
dbExecute(con, "INSTALL httpfs")
dbExecute(con, "INSTALL delta")
dbExecute(con, "INSTALL spatial")

# Carregar a extensão na sessão atual (necessário sempre)
dbExecute(con, "LOAD httpfs")
dbExecute(con, "LOAD delta")

# Listar extensões instaladas
dbGetQuery(con, "
  SELECT extension_name, installed, loaded
  FROM   duckdb_extensions()
  WHERE  installed = TRUE") |>
  as_tibble()

           COUNT(*)                  AS total_voos,
           ROUND(AVG(arr_delay), 2)  AS atraso_medio
  FROM     delta_scan('dados_delta/voos')
  WHERE    arr_delay IS NOT NULL
  GROUP BY origin
  ORDER BY atraso_medio DESC") |>
  as_tibble()

Tip

delta_scan() lê a versão mais recente da tabela Delta Lake. Para ler uma versão específica, use delta_scan('caminho', version = 1).

Extensão httpfs: ler arquivos remotos

con <- dbConnect(duckdb())

  SELECT   COUNT(*)   AS total_linhas,
           MIN(year)  AS ano_min,

  as_tibble()

DuckDB em memória x arquivo persistente

# Em memória: use para análise exploratória
con_mem <- dbConnect(duckdb())

# Arquivo: use quando precisar persistir entre sessões
con_file <- dbConnect(duckdb(), dbdir = "meu_banco.duckdb")

# ATENÇÃO: apenas uma conexão por arquivo ao mesmo tempo
# Isso vai gerar erro:
con_a <- dbConnect(duckdb(), dbdir = "mesmo_banco.duckdb")
con_b <- dbConnect(duckdb(), dbdir = "mesmo_banco.duckdb")
# Error: Could not set lock on file

# Solução: fechar antes de reabrir
dbDisconnect(con_a, shutdown = TRUE)
con_b <- dbConnect(duckdb(), dbdir = "mesmo_banco.duckdb")

Erros comuns e soluções

Situação Causa Solução
Could not set lock on file Arquivo .duckdb aberto em outra conexão dbDisconnect() na conexão anterior antes de reconectar
Binder Error: not found Tabela não registrada na conexão duckdb_register() ou verificar com dbListTables()
IO Error: No files found Caminho do arquivo incorreto Verificar com file.exists()
Extensão não encontrada Extensão não instalada dbExecute(con, "INSTALL nome_ext")
Resultado diferente entre sessões Banco em memória, dados perdidos Usar arquivo persistente com dbdir =
