Bloco 1

O Problema de Memória no R

Como o R armazena dados

O R é uma linguagem orientada à memória principal (RAM). Todo objeto criado, vetores, data frames, listas, é armazenado integralmente na RAM durante a sessão.

Consequência direta: o tamanho máximo de dados que o R consegue manipular é limitado pela RAM disponível.

  • Um data.frame com 1 milhão de linhas e 20 colunas numéricas ocupa aproximadamente 160 MB de RAM
  • Um data.frame com 50 milhões de linhas e 20 colunas ocupa aproximadamente 8 GB
  • Durante operações como mutate() e join(), o R cria cópias intermediárias, multiplicando o consumo

O custo de carregar dados no R

Quando você executa read_csv("arquivo.csv"), o R:

  1. Lê o arquivo do disco linha por linha
  2. Converte cada campo de texto para o tipo correto (parsing)
  3. Aloca memória suficiente para o objeto completo
  4. Copia todos os dados para essa memória
  5. Retorna o data.frame, e somente agora você pode usar os dados

Esse processo carrega 100% dos dados, mesmo que você precise de apenas 1% deles.

Se o arquivo tem 10 GB e você quer filtrar apenas um mês, o R ainda carrega os 10 GB inteiros antes de executar qualquer filtro.

Três situações que travam o R

Situação 1: arquivo maior que a RAM

# Falha com: cannot allocate vector of size X Gb
read_csv("arquivo_50gb.csv")

Situação 2: arquivo cabe na RAM, operações não cabem

Um arquivo de 4 GB com 8 GB de RAM disponível pode travar em operações de mutate() ou join() porque o R cria cópias intermediárias.

Situação 3: múltiplos arquivos acumulados

Carregar arquivos mensais em loop para concatenar esgota a memória progressivamente, mesmo que cada arquivo individual caiba.

A solução: execução preguiçosa

O arrow resolve o problema com execução preguiçosa (lazy evaluation):

  • open_dataset() não lê os dados. Registra onde estão e lê apenas o esquema.
  • Operações dplyr constroem um plano de execução sem executar nada.
  • collect() é o único passo que lê dados da memória, e lê apenas o necessário.

Filtrar 1 mês de um arquivo de 10 anos lê apenas os dados daquele mês do disco, não os 10 anos inteiros.

Tip

Pense no arrow como um intermediário entre o dplyr e o disco. Você escreve o mesmo código que já conhece. O arrow decide o que precisa ser lido.

Bloco 2

O Formato Parquet

O que é o formato Parquet

O Apache Parquet é um formato de armazenamento colunar binário projetado para análise de dados em grande escala. É o formato nativo do ecossistema Arrow.

Diferença fundamental entre CSV e Parquet:

  • CSV: armazena dados linha por linha (orientado a linhas)
  • Parquet: armazena dados coluna por coluna (orientado a colunas)

Para análise de dados, que normalmente opera sobre poucas colunas de muitas linhas, o formato colunar é muito mais eficiente porque lê apenas as colunas necessárias, ignorando as demais completamente.

Por que o Parquet é mais rápido

Imagine uma tabela com 50 colunas e 10 milhões de linhas. Você quer calcular a média de apenas uma coluna.

Com CSV: o R lê todas as 50 colunas de todas as 10 milhões de linhas, extrai a coluna desejada e calcula a média.

Com Parquet: o Arrow lê apenas os blocos da coluna desejada no disco. As outras 49 colunas nunca são lidas.

Característica CSV Parquet
Formato Texto, linha por linha Binário, coluna por coluna
Compressão Nenhuma ou gzip Snappy, Zstd, LZ4, Brotli
Leitura seletiva de colunas Impossível Nativa
Tipos de dados Inferidos na leitura Armazenados no arquivo
Legibilidade humana Sim Não

Codificações e compressão no Parquet

O Parquet aplica duas técnicas de redução de tamanho antes da compressão:

Dictionary encoding: valores que se repetem muito são armazenados uma única vez num dicionário. A coluna armazena apenas o índice do dicionário. Uma coluna com 10 milhões de linhas e apenas 3 valores distintos armazena basicamente um vetor de inteiros pequenos.

Run-length encoding (RLE): sequências de valores iguais são armazenadas como o valor mais a contagem. Uma coluna com 1.000 linhas do mesmo valor armazena apenas o valor e o número 1.000.

Note

O algoritmo de compressão padrão do arrow em R é o Snappy, que prioriza velocidade de leitura e escrita. Para máxima compressão com leitura mais lenta, use Zstd. Para compatibilidade mais ampla, use gzip.

Código: salvando em Parquet

# Salvar com compressão padrão (Snappy)
write_parquet(voos_grande, "dados_aula/parquet/voos.parquet")

# Salvar com Zstd para máxima compressão
write_parquet(
  voos_grande,
  "dados_aula/parquet/voos_zstd.parquet",
  compression = "zstd",
  compression_level = 3)

# Comparar tamanhos
tibble(

  arquivo    = c(

    "dados_aula/parquet/voos_zstd.parquet"),

Bloco 3

Benchmark: CSV vs Parquet

O que vamos medir

Vamos comparar três operações idênticas executadas sobre os mesmos dados em três formatos diferentes:

  1. CSV lido com read_csv() do readr
  2. CSV lido com read_csv_arrow() do arrow
  3. Parquet lido com open_dataset() do arrow

A operação: filtrar voos com atraso de chegada acima de 60 minutos, agrupar por companhia aérea e calcular a média do atraso.

Código: benchmark de leitura e filtro

benchmark_resultado <- mark(
  readr_csv = {
    read_csv("dados_aula/csv/voos.csv", show_col_types = FALSE) |>
      filter(arr_delay > 60) |>
      group_by(carrier) |>
      summarise(media_atraso = mean(arr_delay, na.rm = TRUE))
  },
  arrow_csv = {
    read_csv_arrow("dados_aula/csv/voos.csv", as_data_frame = FALSE) |>
      filter(arr_delay > 60) |>
      group_by(carrier) |>
      summarise(media_atraso = mean(arr_delay, na.rm = TRUE)) |>
      collect()
  },
  arrow_parquet = {
    open_dataset("dados_aula/parquet/voos.parquet") |>
      filter(arr_delay > 60) |>
      group_by(carrier) |>
      summarise(media_atraso = mean(arr_delay, na.rm = TRUE)) |>
      collect()
  },
  iterations = 3,
  check = FALSE)

benchmark_resultado |>
  select(expression, median, mem_alloc)

Bloco 5

Particionamento de Datasets

O que é particionamento

Particionamento divide o dataset em múltiplos arquivos organizados em subpastas, com base nos valores de uma ou mais colunas.

Quando você filtra por uma coluna de partição, o Arrow localiza diretamente as subpastas relevantes e ignora todas as outras, sem ler nenhum arquivo desnecessário.

Estrutura gerada por write_dataset() com partição por origin:

dados_aula/particionado/
├── origin=EWR/
│   └── part-0.parquet
├── origin=JFK/
│   └── part-0.parquet
└── origin=LGA/
    └── part-0.parquet

Código: criando dataset particionado

# Particionar por origin e month para consultas por aeroporto e período
voos_grande |>
  group_by(origin, month) |>
  write_dataset(
    "dados_aula/particionado_avancado",
    format = "parquet")

# Abrir o dataset particionado
ds_part <- open_dataset("dados_aula/particionado_avancado")

# O Arrow já sabe quais partições existem
ds_part$schema

Código: consultando com partição

# Filtrar por origin = "JFK" lê apenas a subpasta origin=JFK/
# Nenhum arquivo de EWR ou LGA é tocado
ds_part <- open_dataset("dados_aula/particionado")

ds_part |>

    n             = n(),

Tip

Regra prática: particione pelas colunas que você filtra com mais frequência. Uma coluna com cardinalidade alta (muitos valores distintos) gera muitas partições pequenas e pode prejudicar o desempenho. Prefira colunas com poucos valores distintos, como mês, ano ou categoria.

Importação Eficiente

read_csv_arrow() vs read_csv()

O arrow oferece read_csv_arrow() como alternativa mais rápida ao read_csv() do readr para CSVs grandes.

# Ler como Arrow Table (permanece lazy)
voos_arrow <- read_csv_arrow(
  "dados_aula/csv/voos.csv",
  as_data_frame = FALSE)

# Especificar esquema para evitar inferência de tipos
esquema <- schema(
  year      = int32(),
  month     = int32(),
  day       = int32(),
  origin    = utf8(),
  dest      = utf8(),
  arr_delay = float64())

voos_typed <- read_csv_arrow(
  "dados_aula/csv/voos.csv",
  schema        = esquema,
  as_data_frame = FALSE)

Estratégia recomendada para importação

O fluxo mais eficiente quando você recebe dados em CSV pela primeira vez:

# Passo 1: ler o CSV com arrow (mais rápido que readr)
dados_brutos <- read_csv_arrow(
  "arquivo_original.csv",
  as_data_frame = FALSE)

# Passo 2: converter e salvar em Parquet
dados_brutos |>
  write_parquet("dados_limpos/arquivo.parquet")

# Passo 3: a partir daqui, sempre usar open_dataset() no Parquet
ds <- open_dataset("dados_limpos/arquivo.parquet")

Tip

Converta seus CSVs para Parquet uma única vez e use o Parquet para todas as análises subsequentes. A conversão é um custo único que se paga a cada leitura posterior.

Lendo múltiplos arquivos de uma vez

# open_dataset() lê um diretório inteiro como um único dataset
# Todos os arquivos devem ter o mesmo esquema
ds_multiplo <- open_dataset(
  "pasta_com_varios_csvs/",
  format = "csv")

# Com Parquet, basta apontar para o diretório
ds_parquet_multi <- open_dataset("pasta_com_varios_parquets/")

# Verificar total de linhas
ds_parquet_multi$num_rows

Dicas de eficiência ao importar

1. Especifique tipos ao ler CSV: a inferência de tipos em CSVs grandes é custosa. Especifique o esquema com schema() para eliminar essa etapa.

2. Use col_select ao ler Parquet: se você não precisa de todas as colunas, use select() antes do collect(). O Parquet lê apenas os blocos das colunas selecionadas.

3. Filtre antes de coletar: sempre aplique filter() antes de collect(). O arrow empurra o filtro para o disco e lê apenas o necessário.

4. Evite collect() desnecessário: se o resultado de uma etapa ainda vai ser usado em outra transformação, não colete antes. Mantenha o pipeline lazy até precisar do resultado final.

Bloco 7

Integração com DuckDB

Por que integrar Arrow com DuckDB

O arrow no modo lazy não suporta todas as funções do R. Funções como median(), quantile() e funções de janela como ntile() e lag() geram erro quando usadas antes do collect().

O duckdb resolve isso sem precisar carregar os dados na memória. A função to_duckdb() transfere o contexto de execução do Arrow para o DuckDB, que suporta um conjunto muito maior de operações SQL.

Important

A integração to_duckdb() não copia os dados para a memória. Ela passa a referência do dataset Arrow para o DuckDB, que lê diretamente do disco. O custo de memória é mínimo.

Código: to_duckdb() para operações avançadas

library(duckdb)

# to_duckdb() converte o dataset Arrow para uma tabela DuckDB
# sem copiar os dados para a memória
ds_parquet |>
  to_duckdb() |>
  group_by(origin) |>
  summarise(
    n        = n(),
    mediana  = median(arr_delay, na.rm = TRUE),
    q25      = quantile(arr_delay, 0.25, na.rm = TRUE),
    q75      = quantile(arr_delay, 0.75, na.rm = TRUE),
    .groups  = "drop") |>
  collect()

Bloco 8

O que o Arrow Suporta e o que Não Suporta

Funções dplyr suportadas no modo lazy

O arrow suporta a maioria das funções do dplyr e tidyr diretamente no modo lazy:

  • filter(), select(), mutate(), rename()
  • group_by(), summarise(), arrange()
  • distinct(), count(), tally()
  • left_join(), inner_join(), right_join()
  • slice_head(), slice_tail(), slice_min(), slice_max()
  • Funções de string do stringr: str_detect(), str_replace(), str_to_lower(), str_ilike() (novo na v23)
  • Funções de data do lubridate: year(), month(), floor_date()
  • nchar() com keepNA (novo na v23)

Funções com suporte limitado ou ausente

Função Status Alternativa
median() em summarise() Não suportado to_duckdb()
quantile() Não suportado to_duckdb()
lag(), lead() Suporte parcial to_duckdb()
Funções de janela (ntile(), rank()) Não suportado to_duckdb()
rowwise() Não suportado collect() antes
UDFs (funções definidas pelo usuário) Não suportado collect() antes

Como identificar o que não é suportado

# Isso vai gerar um erro antes do collect()
ds_parquet |>
  group_by(origin) |>
  summarise(
    mediana = median(arr_delay, na.rm = TRUE)) |>
  collect()

# Error: Function 'median' not found or not supported in Arrow

# Solução 1: collect() antes da operação não suportada
ds_parquet |>
  filter(!is.na(arr_delay)) |>
  collect() |>
  group_by(origin) |>
  summarise(mediana = median(arr_delay))

# Solução 2: to_duckdb() sem collect() intermediário
ds_parquet |>
  filter(!is.na(arr_delay)) |>
  to_duckdb() |>
  group_by(origin) |>
  summarise(mediana = median(arr_delay, na.rm = TRUE)) |>
  collect()

Erros Comuns e Decisões Práticas

Erros comuns: parte 1

Situação Causa Solução
Function not found in Arrow Função não suportada no modo lazy to_duckdb() ou collect() antes
Partição não reconhecida Convenção de nome incorreta nas pastas Usar write_dataset() para criar partições
Tipos incorretos ao ler CSV Inferência de tipos errada Especificar schema()

Erros comuns: parte 2

Situação Causa Solução
collect() lento demais Filtro aplicado após collect() Mover filter() para antes do collect()
Dataset muito fragmentado Muitas partições com arquivos pequenos Repartir com menos colunas de partição
Esquemas incompatíveis entre arquivos Arquivos com colunas diferentes Especificar schema() em open_dataset()
Erro ao instalar em Linux Compilador sem suporte a C++20 (v23+) Ver vignette("install", package = "arrow")

Quando usar cada abordagem

Situação Abordagem
Dados menores que 1 GB read_csv() ou read_parquet() com tidyverse
Dados de 1 GB a 10 GB open_dataset() com dplyr e collect()
Dados maiores que 10 GB open_dataset() com particionamento e dplyr
Consultas com median() ou quantile() to_duckdb() sem collect() intermediário
Funções de janela em dados grandes to_duckdb() sem collect() intermediário
SQL complexo em dados grandes to_duckdb() sem collect()
Dados na nuvem (S3, GCS) open_dataset() com URI do bucket

Resumo do fluxo completo

# 1. Recebeu CSV? Converta para Parquet uma vez
dados_brutos <- read_csv_arrow("dados.csv", as_data_frame = FALSE)
write_parquet(dados_brutos, "dados.parquet")

# 2. Abra sem carregar
ds <- open_dataset("dados.parquet")

# 3. Filtre, selecione, agregue no modo lazy
resultado <- ds |>
  filter(ano == 2024, regiao == "Sul") |>
  select(produto, valor, data) |>
  group_by(produto) |>
  summarise(
    total = sum(valor, na.rm = TRUE),
    n     = n(),
    .groups = "drop") |>
  arrange(desc(total)) |>
  collect()          # <-- somente aqui os dados são lidos

# 4. Precisa de mediana ou quartis? Use DuckDB
ds |>
  to_duckdb() |>
  group_by(regiao) |>
  summarise(mediana = median(valor, na.rm = TRUE)) |>
  collect()
